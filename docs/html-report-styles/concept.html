Rules

  1. Use it for a boundary. Two (at most three) owners, what each holds, what crosses between them, and who may write what. For a full system picture, use architecture.html.
  2. Section 1 is the picture. Owner boxes, the bridge, then the allowed and never rows under it. A reader who stops after section 1 knows the concept.
  3. One color per owner, used the same way in every section: box border, dot, and walkthrough step number.
  4. Rules are rows, not prose. Each ✓ allowed or ✗ never row is one sentence. Put the rule that makes the design work last, with why.
  5. Keep it short. Three to four sections. Long scenario lists and open questions go to the record, not the page.
  6. Use placeholder names (owner A, owner B, item-001). No real people, repos, or record ids in a reference page.
  7. Light theme is the default here; test both.
