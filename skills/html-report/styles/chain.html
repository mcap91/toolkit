Rules

  1. One page covers one initiative. It shows done work collapsed at the top, the next items in build order, and parked work as one strip at the bottom.
  2. Order comes from depends_on, never from dates or ids. A band is a milestone. Arrows run top to bottom only.
  3. Status is the 3px stripe on the card and the chip. Never tint the whole card. One color means one status on every page.
  4. Exactly one card carries .accent ("next") per band. More than one means the order is not decided.
  5. Use the fork and merge only for a real parallel pair. Show at most one fork per band. More branches means the band needs splitting.
  6. Each card holds an id, a plain title of one line, and at most one meta line of proof (a commit, a count). Reasoning stays in the records.
  7. Each band that has a gate shows it in .gate: one pass/fail sentence.
  8. The next-actions callout holds at most five items. Each item names who acts.
  9. Code generates the page from the records. The stamp says when, and says that the records win.
  10. Mono font for the page, sans font for titles and the h1. No shadows, no gradients except the grid paper.
  11. Test both themes. The layout collapses to one column below 760px.
