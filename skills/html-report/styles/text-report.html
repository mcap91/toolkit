Rules

For a prose report: a status write-up, an investigation, a proposal, a postmortem. Use science-report.html when the page carries charts. Add rules with a date.

Shape

  1. Answer first. The answer box holds the result. No context, plan, or preamble above it.
  2. Then the fixed order: action items, decisions, recommendation, explanation. Skip an empty part. Do not reorder.
  3. Steps are numbered, one bounded action each, fewest steps that work. Items with no order are bullets.
  4. Lists cap at five. A ranked five beats a full ten. Split the rest into "now" and "later".
  5. Close with one question, or with the one next action when nothing is open.

Voice

  1. Follow the write-plain rules: active voice, short sentences, the plain word, no em dashes, no filler.
  2. Instruction sentences 20 words max. Description sentences 25 words max.
  3. One word for one meaning. Keep the articles. No idioms.
  4. Errors state location, cause, fix, with no alarm language.
  5. Quote real captures for facts about outside systems. Never paraphrase an output shape.

Visual rules

  • One prose column, 720px wide (about 70 characters a line). Tables and code blocks stay inside it.
  • Three callout colors only: decide (purple), warn (orange), note (grey). The answer box is blue. No other color in prose.
  • No charts. A page that needs a chart uses science-report.html.
  • Light and dark themes via data-theme. Test both.

Checks before publishing

  • Reading only the answer box and the closing line tells the reader what happened and what to do.
  • Zero internal vocabulary outside the footer, unless the reader works in that repo.
  • grep -nPi '[\x{2013}\x{2014}]|\b(leverag|utiliz|robust|seamless)' <file> is clean outside code and CSS.
